# مدیریت اقساط، نسخهٔ نصبی اندروید

این مخزن، برنامهٔ وب «مدیریت اقساط» (نسخهٔ ۶ با چهار سبک ظاهری) را با [Capacitor](https://capacitorjs.com) داخل یک برنامهٔ اندرویدی می‌گذارد و GitHub Actions آن را به یک فایل `APK` قابل نصب تبدیل می‌کند. نیازی به Android Studio یا نصب چیزی روی کامپیوتر نیست.

> تمام ساخت روی سرورهای GitHub انجام می‌شود. اسکریپت‌های این پروژه را جداگانه آزمایش کرده‌ام، ولی خود ساخت APK را من نتوانستم اجرا کنم. اگر بار اول خطایی دیدی، بخش «عیب‌یابی» پایین را بخوان و متن خطا را برایم بفرست.

## محتویات

| مسیر | کار |
|---|---|
| `src/` | فایل‌های برنامه (`index.html` و آیکون‌ها). تغییر ظاهر یا امکانات از اینجا انجام می‌شود. |
| `assets/` | آیکون و صفحهٔ شروع اندروید (آیکون تطبیقی، صفحهٔ شروع روشن و تیره). |
| `capacitor.config.json` | نام برنامه و شناسهٔ بسته (`appId`). |
| `scripts/` | آماده‌سازی فایل‌ها و تنظیمات اندروید. |
| `android-overrides/` | کد و منابع بومی اندروید: ویجت صفحهٔ اصلی، پلاگین ارتباط برنامه با ویجت و آیکون اعلان. |
| `keystore/` | کلید امضای آمادهٔ برنامه (برای نصب شخصی). |
| `.github/workflows/build-android.yml` | دستور ساخت خودکار APK. |

## مراحل

### ۱. مخزن بساز و فایل‌ها را بالا ببر
در GitHub یک مخزن جدید بساز (خصوصی هم باشد مشکلی ندارد). بعد در پوشهٔ همین پروژه:

```bash
git init
git add .
git commit -m "اولین نسخه"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

(به‌جای `USERNAME/REPO` نام کاربری و مخزن خودت را بگذار.)

اگر از آپلود دستی در وب‌سایت GitHub استفاده می‌کنی، مطمئن شو پوشهٔ پنهان `.github` هم آپلود شده باشد. بدون آن ساخت خودکار اجرا نمی‌شود. روش `git` یا GitHub Desktop مطمئن‌تر است.

### ۲. ساخت را اجرا کن
با هر `push` روی شاخهٔ `main` ساخت خودکار شروع می‌شود. برای اجرای دستی: تب **Actions** ← **Build Android APK** ← **Run workflow**. حدود ۵ تا ۱۰ دقیقه طول می‌کشد.

### ۳. APK را بگیر
- **راه اول:** در صفحهٔ همان اجرا، پایین صفحه بخش **Artifacts** ← `aghsat-apk` را دانلود کن (یک فایل zip که داخلش `aghsat.apk` است).
- **راه دوم، لینک مستقیم برای گوشی:** یک برچسب نسخه بزن:
  ```bash
  git tag v1.0.0
  git push origin v1.0.0
  ```
  بعد از ساخت، فایل `aghsat.apk` در بخش **Releases** مخزن قرار می‌گیرد و می‌توانی مستقیم روی گوشی دانلودش کنی.

### ۴. روی گوشی نصب کن
1. فایل `aghsat.apk` را به گوشی منتقل کن (یا از Releases دانلود کن) و باز کن.
2. اندروید می‌پرسد اجازهٔ نصب از این منبع داده شود یا نه. «اجازه بده» را بزن (برای برنامهٔ مرورگر یا فایل‌منیجری که APK را از آن باز کرده‌ای).
3. اگر Play Protect هشدار «برنامهٔ ناشناس» داد، «Install anyway» (نصب در هر صورت) را بزن. این هشدار برای هر برنامه‌ای است که از فروشگاه نصب نشده باشد.

## انتقال داده‌های نسخهٔ وب به برنامهٔ اندروید
برنامهٔ نصب‌شده، حافظهٔ جدایی از نسخهٔ وب دارد، پس داده‌های قبلی خودکار منتقل نمی‌شوند. برای انتقال:
1. در نسخهٔ وب قدیمی: **تنظیمات ← کپی پشتیبان به‌صورت متن**.
2. متن را در یادداشت‌ها یا پیام‌های ذخیره‌شده بگذار.
3. در برنامهٔ اندروید: **تنظیمات ← بازیابی از متن پشتیبان** و متن را بچسبان.

در برنامهٔ اندروید، دکمهٔ «ذخیره یا ارسال فایل پشتیبان» منوی اشتراک‌گذاری خود اندروید را باز می‌کند و می‌توانی فایل را در Drive، Files یا پیام‌رسان ذخیره کنی.

## به‌روزرسانی برنامه
1. فایل‌های `src/` را عوض کن (مثلاً `index.html` نسخهٔ جدید).
2. در `package.json` عدد `version` را بالا ببر (مثلاً `1.0.1`). شمارهٔ داخلی نسخه (`versionCode`) خودکار از شمارهٔ اجرای GitHub گرفته می‌شود.
3. `push` کن و APK جدید را بگیر. نصبش روی نسخهٔ قبلی، داده‌ها را نگه می‌دارد.

> نصب روی نسخهٔ قبلی فقط وقتی کار می‌کند که هر دو با **یک کلید امضا** ساخته شده باشند. اگر بعداً کلید را عوض کنی (بخش پایین)، اندروید خطای «App not installed» می‌دهد و باید اول برنامه را پاک کنی. پیش از آن حتماً پشتیبان بگیر.

## کلید امضای اختصاصی (توصیه‌شده)
به‌طور پیش‌فرض APK با کلید آمادهٔ داخل `keystore/` امضا می‌شود. این کلید در مخزن موجود است، یعنی هر کسی که به مخزن دسترسی داشته باشد می‌تواند APKی با همین امضا بسازد. برای استفادهٔ شخصی مشکلی ندارد. اگر APK را برای دیگران می‌فرستی یا می‌خواهی ببری Play Store، کلید خودت را بساز:

```bash
keytool -genkeypair -v -keystore my-release.keystore -alias aghsat \
  -keyalg RSA -keysize 2048 -validity 10950
base64 -w0 my-release.keystore > keystore.b64     # روی مک: base64 -i my-release.keystore
```

بعد در GitHub: **Settings ← Secrets and variables ← Actions ← New repository secret** و این چهار مقدار را بساز:

| نام | مقدار |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوای فایل `keystore.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز کلیدانبار |
| `ANDROID_KEY_ALIAS` | `aghsat` (یا نامی که دادی) |
| `ANDROID_KEY_PASSWORD` | رمز کلید (اگر همان رمز کلیدانبار است، خالی بگذار) |

فایل `my-release.keystore` و رمزهایش را در جای امن نگه دار. اگر گم شود، دیگر نمی‌توانی نسخهٔ جدیدی بسازی که روی نسخهٔ قبلی نصب شود.

## اعلان سررسید
در برنامهٔ نصب‌شده: **تنظیمات ← اعلان‌ها ← فعال‌سازی اعلان‌ها** و اجازه بده. (اگر هنوز فعال نکرده باشی، یک کارت پیشنهاد هم در صفحهٔ خانه می‌آید.)

- هر سررسید سه اعلان دارد: چند روز قبل (طبق «یادآوری سررسید» در تنظیمات)، روز سررسید و روز بعد از آن. چند سررسیدِ هم‌روز در یک اعلان خلاصه می‌شوند.
- ساعت اعلان قابل انتخاب است (پیش‌فرض ۹ صبح).
- اعلان‌ها با `@capacitor/local-notifications` توسط خود اندروید ثبت می‌شوند. برنامه ۶۰ روز آینده را زمان‌بندی می‌کند و با هر بار باز شدن برنامه و هر تغییر (افزودن، پرداخت، ویرایش، تغییر تنظیمات) دوباره می‌سازد. پرداخت ثبت‌شده اعلان‌هایش را حذف می‌کند.
- بدون سرور و بدون اینترنت کار می‌کند و بعد از ریستارت گوشی هم باقی می‌ماند.
- دکمهٔ «اعلان آزمایشی» پنج ثانیه بعد یک اعلان می‌فرستد تا مطمئن شوی اجازه‌ها درست است.

**اگر اعلان دیر آمد یا نیامد:**
1. تنظیمات گوشی ← برنامه‌ها ← مدیریت اقساط ← باتری ← «بدون محدودیت» (Unrestricted). در شیائومی، سامسونگ، هواوی و اوپو این مهم‌ترین عامل است، چون صرفه‌جویی باتری اعلان را عقب می‌اندازد یا برنامه را می‌بندد. در شیائومی «Autostart» را هم روشن کن.
2. اگر در تنظیمات برنامه دکمهٔ «تنظیم آلارم دقیق» دیده شد، همان‌جا فعالش کن. بدون آن، اندروید اعلان را با چند دقیقه تأخیر می‌فرستد که برای اقساط مشکلی ندارد.
3. در تنظیمات گوشی مطمئن شو اعلان‌های برنامه و کانال «یادآوری سررسید» خاموش نیست.

## ویجت صفحهٔ اصلی
روی صفحهٔ اصلی گوشی انگشتت را نگه دار ← **ویجت‌ها** ← **اقساط**. اندازهٔ پیش‌فرض ۴ در ۲ است و قابل تغییر اندازه است.

- سررسید بعدی (نام، مبلغ و تاریخ شمسی) و دو سررسید بعد از آن را نشان می‌دهد. بالا، مجموع «پرداختنی این ماه» هم هست.
- اگر سررسید گذشته باشد، برچسب و رنگ قرمز می‌شود.
- با لمس ویجت، برنامه باز می‌شود.
- ویجت خودش داده‌ای ندارد. برنامه هر بار که باز می‌شود یا تغییری ثبت می‌شود، متن‌های آماده را به آن می‌دهد. عبارت‌های «فردا» و «۳ روز دیگر» را خود ویجت هر روز (با تغییر تاریخ) تازه می‌کند.
- اگر ویجت پیام «برنامه را یک بار باز کن» را نشان داد، برنامه را یک بار باز کن.

کد ویجت در `android-overrides/` است و هنگام ساخت خودکار به پروژهٔ اندروید اضافه می‌شود (`scripts/patch-android.js`).

## شخصی‌سازی
- **نام برنامه و شناسهٔ بسته:** در `capacitor.config.json` فیلدهای `appName` و `appId` (مثلاً `ir.example.aghsat`). شناسه را **پیش از اولین نصب** عوض کن. با تغییرش، اندروید آن را برنامهٔ جدید می‌بیند.
- **آیکون و صفحهٔ شروع:** فایل‌های `assets/` را عوض کن (آیکون‌ها ۱۰۲۴ در ۱۰۲۴، صفحهٔ شروع ۲۷۳۲ در ۲۷۳۲). `icon-foreground.png` لایهٔ جلویی آیکون تطبیقی است و باید داخل ناحیهٔ مرکزی بماند.
- **فونت:** ساخت خودکار، فونت وزیرمتن را داخل خود برنامه می‌گذارد تا کاملاً آفلاین باشد. اگر بسته در دسترس نبود، همان لینک آنلاین نسخهٔ وب می‌ماند.
- **رنگ نوار وضعیت:** در `scripts/patch-android.js` ثابت `COLOR`.

## محدودیت‌ها
- ویجت فقط نمایشی است. پرداخت را نمی‌شود از روی ویجت ثبت کرد و باید برنامه را باز کنی.
- اعلان‌ها ۶۰ روز آینده را پوشش می‌دهند. اگر بیش از دو ماه برنامه را باز نکنی، بعد از آن اعلانی نمی‌آید.
- پروژه با Capacitor ۶ و `targetSdk` ۳۴ ساخته می‌شود که برای نصب مستقیم APK کاملاً مناسب است. برای انتشار در Google Play به فایل `AAB` و `targetSdk` جدیدتر نیاز داری. در آن صورت باید به Capacitor ۷ یا بالاتر ارتقا بدهی (پایه‌های `@capacitor/*` در `package.json` و `java-version` در workflow).

## عیب‌یابی
- **ساخت قرمز شد:** در تب Actions روی اجرای ناموفق بزن، مرحلهٔ قرمز را باز کن و متن خطا را نگه دار.
  - `npm install` خطا داد: معمولاً نسخهٔ یکی از بسته‌ها پیدا نشده. نام بسته را در خطا ببین.
  - مرحلهٔ `cap add android` یا `gradlew`: متن کامل خطا را برایم بفرست.
  - `apksigner`: رمز یا نام کلید (alias) در Secrets اشتباه است. برای استفاده از کلید آماده، هر چهار Secret را پاک کن.
- **«App not installed» هنگام نصب:** نسخهٔ قبلی با کلید دیگری امضا شده. اول برنامهٔ قبلی را پاک کن (بعد از گرفتن پشتیبان) و دوباره نصب کن.
- **Workflow اصلاً در تب Actions دیده نمی‌شود:** پوشهٔ `.github/workflows` بالا نرفته. با `git` دوباره `push` کن.
